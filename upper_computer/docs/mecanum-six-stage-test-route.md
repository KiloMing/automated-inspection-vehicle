# 麦克纳姆六阶段测试路线

> 原聊天的六阶段正文无法从引用读取。以下是依据本次明确需求重建的执行路线，不冒充原文。已经完成的 Camsense X1 + RF2O + SLAM Toolbox 基本建图成果继续保留；第五阶段做回归，不要求推翻重做。每阶段通过后再进入依赖它的下一阶段。

共同记录：commit、Ubuntu/ROS/软件包版本、几何/控制参数、测试人、日期、日志/rosbag、预期/实际结果。门限是初始工程验收建议，不是已经达成的精度承诺。

## 1. 离线运动学与配置

无电机供电。运行新包 pytest，确认前进全正、左移 -++-、逆时针 -+-+，200 组往返误差小于 1e-9，非法几何/NaN 拒绝，限幅保持方向。展开实车/仿真 Xacro，核对四个关节和半轴距+半轮距，运行旧底盘六组测试。

通过条件：全部单元测试通过；原差速/雷达文件无删除或改写。输出 pytest、编译日志和 geometry.yaml 实测计划。

## 2. Gazebo 底盘与接口

运行 `simulation_acceptance.sh`，检查两个控制器 active、/clock、/scan、/odom、/ground_truth、四轮反馈。执行前后/左右/旋转/斜移；自动脚本覆盖前进、左移、斜移、逆时针，其反向由手工扩展记录。观察 ground truth 与 odom，不能以轮子转动代替机身移动。

通过条件：脚本位移/角度误差在 max(0.06,期望35%) 内；纯横移无明显前后/旋转串扰；停止发送后不迟于参考超时加调度裕量停车。脚本等待0.7秒后测0.5秒漂移≤0.03 m/rad；另外记录速度曲线确定实际停车延迟。雷达持续有效、TF 无双发布。保存 simulation.log 和 rosbag。

## 3. 仿真全向定位与导航

先用新世界建图并保存；停止 SLAM，使用 matching_map 启动 AMCL Omni/Nav2 MPPI Omni。RViz 给初始位置。设置前方、侧方、斜方目标、狭窄通道及障碍，重复同朝向侧向目标，确认 y 命令经过 smoother/collision monitor 后仍非零。不要启用旧差速自动初始位姿或巡航点。

通过条件：10 次目标到达不少于 9 次，无碰撞；位置误差≤0.15 m、角度≤0.15 rad；障碍/扫描失效时停车；无 TF extrapolation 持续报错。记录控制频率与 CPU。失败定位到规划、速度链、TF 或接触模型，不直接上实车。

## 4. 鲁班猫 + STM32 四轮架空联调

先测量 r/lx/ly、滚子 X 布局、电机/编码器极性及雷达外参。明确四通道引脚、驱动与电源，再实现通信契约。四轮离地、可物理急停，逐轮低速 0.5 rad/s 验证顺序和正反；再验证前进、横移、旋转组合。

通过条件：四轮反馈顺序/符号完全正确，稳态轮速误差≤10%；无指令、超时、错误帧、USB 拔插、上位机退出、MCU 重启均能停车；恢复不自动重放旧指令。MCU 和主机各自有超时，急停独立有效。未通过不得落地自动运动。

## 5. 已有实车建图链路回归与里程计校准

继续使用既有 Camsense X1 驱动、RF2O、SLAM Toolbox。首先不接电机，手推/缓慢移动重现 /scan→/odom_rf2o→/map，保存地图和 rosbag。新 real_mapping launch 只是重建候选，先与现场配置逐项对照。测量雷达外参，唯一 TF 源；不要同时启动轮式与 RF2O odom TF。

架空阶段通过后，在空旷区分别直行1 m、横移1 m、旋转360°各3次，比较尺测、轮式 odom、RF2O；再做矩形回路。通过条件：基本建图成果不退化、无重复墙明显增大、话题/TF 连续；初始相对误差目标≤10%，未达成就调整轮径/几何/符号/摩擦，不靠篡改地图掩盖。保存校准参数和原始记录。

## 6. 实车全向导航与巡检验收

完成实际 MCU 接口和单一 odom 来源选择后，使用 real_map、use_sim_time=false、AMCL Omni；初始线速度≤0.1 m/s、角速度≤0.3 rad/s，再逐级提升。先空场侧移目标，再通道、障碍、失联、急停、10次往返与30分钟连续运行。最后接回原巡检语音/拍照任务，检查新场地图与巡检点。

通过条件：目标成功率≥90%、无碰撞或失控；误差初始目标≤0.15 m/0.15 rad；扫描失效/通信断开停车；鲁班猫无持续降频导致控制超时，记录温度、电源、CPU、MPPI 频率和时延。所有失败及未测项逐条保留，不能以一次地图显示正常替代整车验收。
