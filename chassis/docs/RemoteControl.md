# 双摇杆遥控

UART.c/h未修改，USART1仍使用115200，PA10接蓝牙TX；不发送遥测。模块波特率须与现有串口匹配。
RemoteSerial在现有UART_Init之后启用USART1接收中断；中断只缓存字节及接收时间，主循环每次最多处理64字节，将完整流交给RemoteControl。UART.c/h、引脚和波特率未改，不使用阻塞收字符串函数。
电机PID计算只屏蔽TIM1采样中断，不再全局关中断，USART1和HWT101接收可在PID计算与100us换向延时期间运行。错误或队列溢出时丢弃不完整数据并停车；队列中超过300ms的旧字节仍会丢弃并停车，此检查不针对没有新数据的空闲状态。
原g/r/h/s/z不再解析。HeadingControl的独立定角接口保留，但不与遥控同时执行，避免争用电机目标。

接收[j,LX,LY,RX,RY]或[joystick,LX,LY,RX,RY]，四个整数必须在-100到100，逗号分隔；字段前后允许空格和制表符，例如[j, -1, 100, 0, 0]。不接受数字内部空白、缺失字段或多余字段。
左Y控制前后，右X控制左右；左X、右Y忽略。上/右为正。左轮为电机1，右轮为电机2。
首次上电直接接受第一条有效摇杆指令，不要求APP发送回中帧。异常停车后仍需收到有效回中帧才能恢复。

RemoteControl.h提供死区5、最大直行0.4m/s、转向目标变化45度/s、加速度0.5m/s²等宏。REMOTE_TIMEOUT_MS默认0，关闭遥控收包超时停车。
REMOTE_STARTUP_PWM=200表示20%起步PWM下限，仅在编码增量绝对值不超过2、目标非零且PID要求驱动时生效；转起来后恢复原PID输出。回中或故障停车不受此下限影响。设为0可禁用，低速启停可能更明显，需实车验证。
遥控沿用HeadingControl.h角度环增益，速度内环参数不变。20ms处理运动指令，角度积分仅在收到新HWT角度时更新。
左轮目标=基础速度-纠偏量，右轮目标=基础速度+纠偏量；前后均保持车头航向。
右摇杆修改目标航向，领先实际航向最多20度；回中时等待转动稳定再锁定当前航向。
两轴回中直接停车并退出纠偏。换向先等两轮接近零速100ms。目标混合后统一限幅。

APP按摇杆变化发送完整帧即可，推住不动时持续执行最后一条有效指令，收到回中帧停车。坏帧不覆盖有效指令。
关闭收包超时后，仅凭串口静默不能识别蓝牙断开，因此断开不会自动停车。后续APP支持周期心跳时，可将REMOTE_TIMEOUT_MS设为非零以恢复超时停车。
角度失效或电机处理超时仍会停车，并要求重新回中。
若HWT连续角因断流失效，需要停车恢复角度参考或重启，再回中重新操作。
该控制保持航向，不能纠正横向位移回到原路径。实车速度、低速转向和抗扰效果需验证。

## 参考工程对照

参考版本：[MCU-slave-device PIDtest](https://github.com/KiloMing/MCU-slave-device/tree/c433766ccaab0fea1321d5422a124186028dae10)。
其new_project/App/buleteethtest.c通过UART_StartReceiveIT收包，在主循环解析和计算轮速；new_project/Hardware/UART.c使用HAL单字节接收回调。当前工程借鉴接收与控制分离方式，使用标准外设库和环形缓存，未复制HAL驱动或改引脚。
参考分支为四轮麦克纳姆控制，左杆旋转、右杆平移，没有HWT航向环，也未设置遥控收包超时。当前保留用户要求的两轮差速、左Y前后、右X转向和HWT闭环，默认同样保持最后一条指令；不能照搬其轮速公式和PID数值。
内存remote_debug记录收包数、拒绝包数、接收错误及状态；不额外发送串口数据。
